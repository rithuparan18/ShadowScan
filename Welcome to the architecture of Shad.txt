Welcome to the architecture of ShadowScan Pro. If you are seeing this project for the first time, think of it not just as a "scanner," but as an Automated Intelligence Pipeline.

In modern security operations, finding a single IP is easy; mapping the entire attack surface of a global corporation is hard. ShadowScan Pro is designed to solve that "at-scale" problem through a modular, high-speed approach.

1. The High-Level Architecture
ShadowScan follows a Tiered Pipeline design. Instead of doing everything at once, it breaks the reconnaissance process into logical stages, ensuring that data from one stage informs the next.

Tier 1: Passive Intelligence (The Stealth Layer)
ShadowScan starts by "listening" before it "touches." By querying external databases like HackerTarget and CRT.sh (Certificate Transparency logs), it identifies subdomains that exist in the public record.

Why this matters: It allows you to find assets that might be hidden behind firewalls or hosted on third-party clouds without sending a single packet to the target's infrastructure.

Tier 2: Active Discovery & Validation
Once it has a list of potential subdomains, the scanner.py module takes over. It performs active DNS resolution to see which of those subdomains are actually "alive" (mapped to an IP address).

Technical Implementation: It uses the dnspython library to handle bulk resolutions and immediately identifies the IP Address and Hosting Provider.

Tier 3: Enumeration & Deep Inspection
Now that we have a live list, ShadowScan moves into high-value enumeration:

Port Scanning: It checks common "entry point" ports (80, 443, 22, 3389).

Secret Hunting (secrets.py): This is the "Deep Dive." It scrapes public-facing JavaScript files and uses Regex (Regular Expression) patterns to find API keys, JWTs, and AWS tokens.

Tier 4: Structured Output
Everything is funneled into a thread-safe JSON report. In a professional environment, raw text is useless; JSON allows this data to be fed into other tools like Splunk or ElasticSearch for further analysis.

2. Deep-Dive: The Code Modules
main.py – The Command Center
This is the "Brain" of the operation.

Argument Handling: It uses argparse to allow the user to toggle features (e.g., -s for secret hunting).

Workflow Orchestration: It decides the order of operations. It ensures that the passive discovery finishes before the port scanner starts, preventing race conditions.

The UI: It uses the Rich library to provide a real-time, colorized dashboard so an analyst can see results as they happen.

scanner.py – The Engine Room
This module is built for Concurrency.

ThreadPoolExecutor: Instead of scanning one subdomain at a time, it spins up hundreds of "worker threads" (defaulting to 500+ targets simultaneously).

TCP Connect Logic: It attempts to establish a connection to high-value ports. If the connection is successful, it "grabs the banner"—reading the initial response from the server (e.g., SSH-2.0-OpenSSH_8.2p1) to fingerprint the software version.

secrets.py – The Intelligence Specialist
This is the "Greedy" module. It focuses on Layer 7 (Application) vulnerabilities.

Pattern Matching: It contains a library of "Signatures." For example, an AWS key has a very specific format (AKIA...).

Scraping Logic: It requests JS files found on the web pages, searches for these signatures, and flags them. Finding a hardcoded API key is often a "Critical" finding in a penetration test.

bruteforce.py – The Path Finder
This module targets the "Hidden" attack surface.

Logic: It takes a wordlist (e.g., admin, backup, config) and appends it to the URL.

Outcome: It looks for 200 OK or 403 Forbidden responses, which indicate that a file or directory exists even if it isn't linked anywhere on the main site.

3. Key Design Philosophy: Why "Modular"?
The most important part of ShadowScan is the modules/ folder. By separating the logic, the framework becomes "Future-Proof."

Extensibility: If you want to add a module to detect "Subdomain Takeovers," you don't have to rewrite the whole engine. You simply create takeover.py, add your logic, and import it into main.py.

Maintenance: If the HackerTarget API changes, you only have to update one section of code in the scanner module without touching the secret hunter or the CLI logic.

4. Operational Impact
From a "Fresh Face" perspective, ShadowScan Pro transforms a manual, 5-hour task into a 5-minute automated scan. It provides the Context an analyst needs:

What is our infrastructure? (Subdomains)

Where is it hosted? (IP/Provider)

How is it vulnerable? (Open Ports/Banner Grabbing)

What secrets are exposed? (JS Scraping)

This project demonstrates a transition from a "Script Kiddie" mindset (running someone else's tool) to an Engineer's mindset (building a structured framework to handle enterprise-level data).
